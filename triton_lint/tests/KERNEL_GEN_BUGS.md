# kernel_gen bugs — audit history

Data-flow bugs found by the `audit-kernel-gen` skill: silent drops at a seam, the wrong
element chosen out of a completion, misaligned arrays. Each open bug has a strict-xfail
test (a fix flips it to XPASS, which errors, which forces deleting the row). Cataloguing
and fixing are separate passes — a row here means "found, reproduced, not yet fixed."

Rows marked *(fixed)* were caught and fixed in the same pass, so they never held a
strict-xfail marker. Each one's regression test was written first and verified to fail on
the unfixed code — the same standard, applied in one sitting instead of two.

| ID | module:seam | what is wrong, mechanically | what it harms |
|----|-------------|-----------------------------|---------------|
| KGEN-1 | text:extract_code_block | *(fixed this session)* took the **first** fenced block; reasoning models revise in the open, so the first block is a superseded draft or a bare fragment | shipped the wrong kernel; eval scored it zero. Regression-tested (passing) in `test_core_model.py`. |
| KGEN-2 | text:extract_code_block | *(fixed this session)* ignored an **unterminated** final block: the fenced-block regex requires a closing ```` ``` ````, so when the model's last, best kernel was cut off by `max_tokens` (no closing fence) it was invisible, and extraction fell back to an earlier **complete** block — often a superseded draft, and 29 times a bare fragment with no `ModelNew`. KGEN-1's fix ranked only *closed* blocks, so it did not address this. Measured: **83 of 3416** real Qwen3.6 completions (level 1+2) shipped the wrong block over a valid unterminated final `ModelNew`. Worst real case: `level_1_problem_13_sample_5`, two closed fragment blocks (226, 117 ch, neither `ModelNew`) + a 3239-ch unterminated final `ModelNew` → shipped the 117-ch fragment. **Fix:** `extract_code_block` now recovers the tail (an opening fence past the last closed block with no closing fence before EOF) as a ranked candidate; it flows through the same ranking, so a truncated tail that fails to parse still loses to a complete block. Regression-tested (passing) in `unit/test_text.py` and on real data in `integration/test_golden_corpus.py`. | ships a draft or fragment for the hardest problems (the ones long enough to hit the cap); eval scores a correct completion zero; the repair loop refines a strawman. Masked because a shipped fragment does not raise — indistinguishable at eval from a genuine model failure. |
| KGEN-3 | text:`_fenced_blocks` | *(fixed this session)* `_FENCE = ```` r"```(?:python\|py)?[ \t]*\r?\n(.*?)```" ```` cannot distinguish an **opening** fence from a **closing** one — a bare ```` ```\n ```` reads as an opener either way. When a lone/stray closing fence sits before the real block (the model closes an in-reasoning code example with ```` ```\n ````, or writes ```` ```\n</think> ````), the non-greedy `(.*?)` pairs that stray closer with the **real block's** ```` ```python ```` opener: it captures the inter-block prose (`</think>`, `Code structure:`) as the "block" and **consumes the real opener**, so the model's complete `ModelNew` is never seen as a fenced block at all. KGEN-1 and KGEN-2 both operate on `_FENCE`'s *output*, so neither touches this — the mis-pairing is upstream, in `_FENCE` itself. Trigger in the wild: a malformed opener (```` ```tl ```` inline, no newline) that `_FENCE` skips, or a stray closer, offsetting the open→close pairing by one for the rest of the completion. Measured: **≥12 of 6982** real Qwen3.6 completions (level 1+2, both think modes) drop a complete parseable `ModelNew` for a prose scrap; conservative lower bound (a line-anchored oracle also mis-pairs some, e.g. `level_2_problem_79_sample_8`, so the true count is higher). Worst real cases: `level_2_problem_2_sample_1` (33 kch, real 3339-ch `ModelNew` at char 32767 → ships `'Code structure:'`, 15 ch) and `level_2_problem_79_sample_8` (ships `'</think>'`, 8 ch). Strict-xfail repro `unit/test_text.py::test_a_stray_closing_fence_does_not_swallow_the_real_block`; real cases `integration/test_golden_corpus.py` category `kgen3_broken` (`level_2_problem_100_sample_4`, `level_1_problem_29_sample_1`). **Fix:** `extract_code_block` now delimits blocks with `_fenced_blocks`, an open/close walk over fence markers — an info-tagged ```` ```python ```` opens, a bare ```` ``` ```` closes, and a bare ```` ``` ```` seen *outside* a block is a stray closer and is skipped. Markers are matched anywhere on the line (the two-pass seam puts ```` ```python ```` mid-line ~13% of the time) but only through end-of-line (so an inline ```` ```tl.minimum(x) ```` in prose is not a fence). Verified on all 6,982 real completions: **0 remaining misses** (was ≥12), **0 regressions** in a before/after diff (6,928 identical, 54 changed and every change same-or-better). Regression-tested in `unit/test_text.py` (synthetic repro + control + back-to-back openers + compound KGEN-2/3), on real data in `integration/test_golden_corpus.py` (category `kgen3_broken`), and as an invariant in `properties/test_text_metamorphic.py` (a stray closing fence before any well-formed completion is a no-op). | ships prose or an empty string for a model **success**; eval scores a correct, complete kernel zero; the repair loop refines a strawman. Same masking as KGEN-1/2: a shipped scrap does not raise, so it is indistinguishable at eval from a genuine model failure. |
| KGEN-9 | text:`_fenced_blocks` / `extract_code_block` | *(fixed)* an **empty** fenced block ranked as a valid candidate and won. `ast.parse("")` succeeds, so an empty block landed in `parseable`, and with no `ModelNew` anywhere in `submissions` the ranking returned `parseable[-1]` — the empty string. The two-pass sampler manufactures exactly that block: `text = PLAN_PREFIX + plan + CODE_FENCE + code`, so when pass 2 returns nothing the injected ```` ```python ```` trails the completion with no content after it. The model meanwhile had written its whole answer *unfenced* inside the plan half. Measured: **21 of 10,510** real traced attempts extracted to `""` while their raw held a complete `class ModelNew`; all 21 had `passes=2`, `plan_finish='stop'`, and exactly one empty block. The refined side survived it (`Trajectory.final()` picks another round), but **round 0 is the paired baseline** — 12 baseline kernels were written as 0-byte files for generations that succeeded, biasing the very comparison the arm exists to make. The golden corpus had catalogued two such completions as `model_failed`. **Fix:** `_fenced_blocks` drops empty blocks (an empty string is never the model's answer); the no-fence path replaces every fence marker with a newline rather than deleting it (the injected fence lands glued to the model's last line, `return f(x)```python`, so deleting it would splice that line onto the next) and falls back to `_largest_parseable_prefix`, gated on `ENTRY_CLASS` so a salvage with no submission is discarded. Verified on all 10,510 real completions: 10,469 identical, 41 changed, **32 unusable → callable with imports and a `@triton.jit`**, 1 → partial, 8 unchanged-unusable, **0 regressions**; residual extract-to-empty is now **0**. NOT extended to fenced blocks — see `_largest_parseable_prefix`'s docstring for the measurement that rejected it. Regression-tested in `unit/test_text.py` (5 cases) and on real data in `integration/test_golden_corpus.py` category `kgen9_broken`. | ships `""` for a model **success**; eval scores a correct kernel zero. Worst on the baseline half, where there is no later round to recover it — so the loop's measured benefit was inflated. Masked because an empty file does not raise. |
