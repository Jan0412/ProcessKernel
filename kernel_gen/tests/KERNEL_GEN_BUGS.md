# kernel_gen bugs — audit history

Data-flow bugs found by the `audit-kernel-gen` skill: silent drops at a seam, the wrong
element chosen out of a completion, misaligned arrays. Each open bug has a strict-xfail
test (a fix flips it to XPASS, which errors, which forces deleting the row). Cataloguing
and fixing are separate passes — a row here means "found, reproduced, not yet fixed."

Rows marked *(fixed)* were caught and fixed in the same pass, so they never held a
strict-xfail marker. Each one's regression test was written first and verified to fail on
the unfixed code — the same standard, applied in one sitting instead of two.

**KGEN-4…KGEN-8 (2026-07-30)** came from a full-package audit rather than the skill: 749
tests green, 100% branch coverage on `core/`, 136/136 mutants killed, and these five still
invisible. None of them changes which kernel is generated or written — the kernel path
(`run_rounds` → `Trajectory.final()` → `write_kernels`) is untouched by all five. They cost
PRM training data, printed instructions, and two vacuous seam assertions.

| KGEN-3 | text:`_fenced_blocks` | *(fixed this session)* `_FENCE = ```` r"```(?:python\|py)?[ \t]*\r?\n(.*?)```" ```` cannot distinguish an **opening** fence from a **closing** one — a bare ```` ```\n ```` reads as an opener either way. Regression-tested in `unit/test_text.py` (synthetic repro + control + back-to-back openers + compound KGEN-2/3), on real data in `integration/test_golden_corpus.py` (category `kgen3_broken`), and as an invariant in `properties/test_text_metamorphic.py` (a stray closing fence before any well-formed completion is a no-op). | ships prose or an empty string for a model **success**; eval scores a correct, complete kernel zero; the repair loop refines a strawman.
